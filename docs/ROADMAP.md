# План

Каждый шаг закрывается оракулом — скриптом, который запускает реальные игры и печатает PASS/FAIL.

## 1. Протокол и стенд (здесь, сейчас)
- [x] Модель владения и протокол из SemCraft 2 ([ARCHITECTURE](ARCHITECTURE.md), [PROTOCOL](PROTOCOL.md)).
- [x] `tools/echo_guest.py` — минимальный гость: принимает плагин Sam, показывает его сообщения.

## 2. Ядро хозяина Sam (из SemCraft 2)
- [ ] Вынести из `SemCraft2/sam/Source` части без Minecraft (связь, вклейка, экспорт уровня, муверы, монстры,
      оружие, твёрдые браши, физика по чужим формулам, экраны) в библиотеку `host-sam/` с интерфейсом гостя:
      гость регистрирует обработчики сообщений и свои механики (как элитры — `Glide.cpp`).
- [ ] Порт, имя общей памяти и папку файлов — из настроек (сейчас `25610`, `Local\SemCraft2Frame`, `%TEMP%\SemCraft2`).
- [ ] SemCraft 2 собирается поверх ядра; его оракулы (`test_wall`, `test_movers`, `test_glide`, `test_deeper`, …)
      проходят без изменений.

## 3. Второй гость
Кандидаты (выбор — с владельцем проекта): игра с модами на Java/C# (быстро: свой адаптер, как Fabric-мод), игра на
Doom-движке через исходный порт (GZDoom: свой рендер в общую память), либо правила гостя без его движка (headless —
для «числовых» игр). Первый срез — кадр гостя в Sam с глубиной на одном уровне и куб в правильном месте.

## 4. Сэм в другой игре (обратный мост)
- [ ] Механики Sam как гость: монстры Sam (их ИИ и урон считает Sam, хозяин рисует и сталкивает), оружие Sam в руках
      игрока хозяина.
- [ ] Первый хозяин — Minecraft (мод SemCraft 2 уже умеет двойников и экраны): «Серьёзный Сэм в Minecraft».

## Правила
- Только одиночная игра или свои серверы, никаких онлайн-игр с античитом.
- Никаких файлов игр в репозиториях; ассеты берутся с установки игрока.
- Тест-стенды не трогают сохранения игрока (копия `SaveGame` перед запуском).
